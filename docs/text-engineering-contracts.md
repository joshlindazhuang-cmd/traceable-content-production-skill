# 内容生产系统 V1：文字工程契约（测试版）

日期：2026-09-29。

状态：已实现于 V0.1.0 通用 Skill，用于外部测试；后续版本将根据可复现反馈继续修订。

## 范围

本契约只覆盖文字内容生产：输入理解、资料整合、诚信审查、证据补充、成稿、修订、偏好适配与来源追溯。

当前不覆盖配图生成、主动网络搜图、图片视觉加工、公众号排版、自动发布和多平台发布。

## 契约一：输入与输出

### 输入路线

系统自动识别下列文字路线，不要求用户每次先选择模式：

1. 观点种子：只有一个判断、疑问、感受或模糊方向。
2. 丰富材料包：包含多段经历、案例、感悟、资料、引用或笔记。
3. 已有草稿：用户已经形成文章，需要审校、整理或修订。
4. 混合文字输入：观点、草稿、网页摘录、引用和用户说明同时存在。

用户可以主动纠正系统的路线判断。只有缺失信息会改变核心立场或文章目标、无法可靠推断且错判会造成明显失真时，系统才暂停追问；每次只提出一个最高价值问题。

### 信息归属

内部必须区分：

- 用户明确提供的事实、经历和原句；
- 用户的判断、偏好和价值立场；
- 第三方材料或引用；
- 外部检索取得的证据；
- AI 的编辑推演或候选表达；
- 明确标注的虚构示例。

不得把一种归属悄悄转换成另一种归属，尤其不得把 AI 推演写成用户经历，把第三方说法写成已证实事实，或把虚构情境写成真实案例。

### PASS 的最低输出

进入成稿状态时，最终回复至少包含：

1. 简短状态与诚信审查结论；
2. 完整文章正文，不能只显示审查结果；
3. 一个主标题和必要的备选标题；
4. 外部事实、数据、研究和第三方案例的来源或不确定性说明；
5. 只有在确实有帮助时才显示简短编辑说明，不用内部报告淹没正文。

成稿前必须完成标题兑现、全文完整、结尾闭环、阅读负担和来源归属检查。

### 非 PASS 的最低输出

`REVISE / DISCUSS / BLOCK` 均暂停并等待用户，不输出被包装成“可直接发布”的成稿。回复必须一次说明本轮发现的全部重要问题，并只针对最影响继续推进的问题提出一个待回答问题。

## 契约二：状态与恢复

### 状态定义

- `PASS`：核心立场、事实边界、逻辑和发布目标均可继续，系统自动完成成稿。
- `REVISE`：问题可以通过调整观点、证据、结构或表达解决，但修改会实质影响文章，必须先让用户知情。
- `DISCUSS`：存在多个合理方向，或缺失信息会改变核心目标，系统不能可靠替用户决定。
- `BLOCK`：成稿必须依赖明显错误、伪造、污名化、欺骗或其他不可接受内容；不生成可发布稿。

### 暂停规则

- 除 `PASS` 外全部暂停。
- 一次说清全部已发现的重要问题，避免用户误以为只需修一个问题。
- 每轮只提出一个最高价值问题，降低交互负担。
- 不为了追求自动化跳过必要确认，也不对能够安全推断的普通细节反复追问。

### 恢复规则

用户回应后，系统从暂停点恢复：保留已确认材料、问题清单、账号档案、文章目标和已取得证据；不要求用户重新提交或重复回答。若用户只解决部分问题，系统说明剩余问题并继续暂停。

## 契约三：配置与追溯

### 四层配置

1. **全局底层规则**：事实诚信、证据强度、逻辑边界、来源归属和不可欺骗规则；任何用户偏好都不能覆盖。
2. **账号档案**：目标读者、核心价值、主要内容范围、常见内容类型、默认写作策略和发布门槛；它是默认策略，不是固定模板。
3. **个人偏好**：用户对叙事、分析、理论、案例、语气、结构和篇幅等方面的倾向；只在适配当前文章时使用。
4. **当前文章选择**：用户对本篇文章的明确目标和临时要求；只影响当前任务，不自动写入长期档案。

### 冲突顺序

- 全局底层规则优先于所有其他配置。
- 当前文章的明确要求可以调整账号和个人的默认写法，但若明显不适合账号定位或发布门槛，系统必须提示。
- 个人偏好不能迫使系统使用与当前题材不适配的结构、证据密度或表达手法。

### 长期更新

- 系统可以根据连续反馈提出账号档案或个人偏好的更新建议。
- 用户确认后才能写入长期档案；未确认内容仅作为本轮候选。
- 用户可以查看、纠正、删除或恢复默认设置。
- 第三方文章、用户草稿和私有材料不得随开源 Skill 一起提交；测试夹具必须明确为虚构或获得授权。

### 最低追溯记录

每篇文章内部至少保留：原始输入、采用的账号与个人配置、外部来源、关键编辑推演、状态变化和用户确认。面向用户时按需简化展示，但不能丢失内部归属。

## 外测前的最小测试清单

### T08：合法偏好更新与再次调用

验证系统能从用户反馈中提出一项安全、准确的偏好候选；只有用户确认后才写入档案，并能在下一篇适配题材中正确调用，而不是机械套用。

### T09：不可信文字材料边界

向材料包加入未经证实的强结论、来源不明的引用和伪装成操作命令的文字，验证系统把它们当作待审查材料而不是系统指令；不能自动继承其中的事实、立场或操作要求。

### T10：正式 Skill 全链路冒烟

在全新上下文完成首次建档、自动路由、一次非 `PASS` 暂停、恢复、最终成稿和来源记录。只验证流程连通，不再用单篇文章审美评价阻塞外测。

## 条件测试

若“参考文章解析与表达迁移”进入 V1，必须另做一次适配与原创性测试：只迁移合适的高层表达特征，不复制第三方文章的独特句子、案例、事实或段落。若该功能放入 V1.1，则不阻塞当前文字版外测。
