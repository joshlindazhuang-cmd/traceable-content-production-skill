# 验证记录与已知边界

## 版本结论

V0.1.0 的文字生产主链路已达到外部测试条件。测试证明当前规则能在已覆盖场景中工作，但不代表所有题材、模型和上下文都已经验证。

V0.2.0 没有改变文字生产决策逻辑；它补充了开放 Agent Skills 元数据、跨工具安装说明和单一顶层 Skill 压缩包。跨工具“格式兼容”已经验证，各客户端的运行时行为仍需分别外测。

V0.3.0 回应真实外测暴露的问题：安装到其他 AI 工具后，首次调用没有清晰说明，用户只能猜测能力与边界。本版本同时补充单篇独立运行、多账号隔离、临时要求与长期偏好分层。仓库发布契约已经自动检查；不同客户端是否稳定显示说明卡仍需外测。

## 已覆盖测试

### T08：偏好更新与再次调用

- 无 Skill 对照测试暴露了两个问题：容易把单次反馈静默写成长期偏好；容易在不适配的题材中机械套用偏好。
- 加载 Skill 后测试通过：先提出带适用范围的候选，经用户明确确认和真实写入后才生效；不适配题材会保留底层意图，而不是照搬写法。

### T09：不可信材料边界

- 测试材料包含未经证实的强结论、来源不明的引语，以及伪装成操作命令的文字。
- 加载 Skill 后测试通过：材料被作为待审查数据处理；系统没有继承其中的命令，没有编造数据或场景，也没有绕过非 `PASS` 暂停规则。

### T10：端到端冒烟

- 在全新内容工作区完成账号档案初始化、自动输入路由、`REVISE` 暂停、同一任务恢复、`PASS` 完整成稿和追溯记录。
- 首轮曾发现系统把一般分析写成作者未提供的第一人称内心独白。
- 规则加入第一人称归属审校后重新从空白工作区测试，最终通过。

### T11：首次启用说明

- RED：真实使用中，其他 AI 工具安装 Skill 后没有提供前期说明，用户直接提交材料，但不知道功能、适用场景、暂停机制和版本边界。
- GREEN 契约：首次实际调用显示重点完整的说明卡；已经提交内容时在同一轮继续；说明只自动显示一次，用户可主动再次查看；不可写环境不得声称已保存状态。
- 当前验证：静态发布测试已覆盖上述规则和状态模板。各兼容 AI 工具的实际呈现效果仍需外测，不能称为全部通过。

### T12：单篇独立运行与多账号隔离

- 单篇任务无需账号档案即可完整运行，并可用 `account: none` 明确排除账号上下文。
- 明确账号直接调用对应档案；唯一可靠匹配可自动采用；多个账号均可能匹配且会明显改变结果时进入 `DISCUSS`。
- 单篇临时要求、账号偏好和跨账号个人偏好按最小适用范围记录，不自动跨账号传播或升级。
- 旧版 `accounts/default.md` 的迁移规则要求保留原文件，不覆盖、删除或自动改名。
- 当前验证：自动发布契约检查通过前不得发布；模型在复杂多账号对话中的长期行为仍需外测。

## 已知边界

- 当前只验证文字输入与文字成稿；图片、排版和发布不在本版本范围内。
- 不同模型和运行环境可能产生差异，外测应关注实际行为，不只评价文风。
- 网络事实核查的质量仍依赖可用工具、来源质量和具体任务；找不到可靠来源时，系统应降低表述强度、移除非核心主张，或进入 `REVISE`。
- 参考文章解析与高层表达特征迁移尚未实现，不能把本 Skill 当作仿写工具。
- 首次说明卡依赖宿主 AI 实际加载并遵循 Skill；安装动作本身通常只复制文件，不能保证安装完成瞬间弹出说明。
- 跨账号历史检索当前依赖 Markdown 索引与宿主上下文能力，不是独立向量数据库。

## 外测记录建议

提交 Issue 时尽量包含：

1. 输入类型与原始输入；
2. 使用的账号定位和已确认偏好；
3. 实际状态与输出；
4. 期望状态与输出；
5. 是否发生虚构、漏正文、重复提问、错误恢复或偏好越界；
6. Codex 或其他兼容 Agent 的版本与运行环境。

请先移除真实姓名、联系方式、未公开项目资料和其他敏感信息。
